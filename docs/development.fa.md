# راه‌اندازی محلی کیوسک گندم

[راهنمای انگلیسی](development.md) · [معرفی ریپو](../README.md)

کیوسک گندم چند سؤال دربارهٔ سلیقه می‌پرسه و عطر پیشنهاد می‌ده. رابط فارسی کیوسک و پنل مدیریت کاتالوگ
با Next.js و React ساخته شده. Django هم کاتالوگ، پیشنهاد عطر و API مدیریت رو فراهم می‌کنه.
دیتابیس محلی SQLite هست؛ برای این راه‌اندازی به PostgreSQL، Redis، Strapi یا داکر نیاز ندارید.

## قبل از شروع

Git، Node.js 22 همراه npm و پایتون 3.12 یا جدیدتر رو نصب کنید. نسخه‌های Next.js 16 و React 19
توی `frontend/package-lock.json` مشخصن؛ پکیج‌ها رو با `npm ci` نصب کنید.
Django 6 به پایتون 3.12 یا جدیدتر نیاز داره. برای پکیج‌های پایتون توی `backend/requirements.txt` بازهٔ نسخه تعیین شده،
ولی لاک‌فایلی که همهٔ نسخه‌ها رو دقیق مشخص کنه نداریم. توی ویندوز از پاورشل استفاده کنید.
اگر با WSL کار می‌کنید، مراحل بش رو توی همون محیط و با پکیج‌ها و محیط پایتون جداگانه انجام بدید.

دسترسی GitLab رو از صاحب ریپو بگیرید. برای اجرای تازهٔ محلی، به اطلاعات ورود پروداکشن یا کلید OpenAI نیاز ندارید؛
وقتی کلیدها خالی هستن، پیشنهادها با الگوریتم پایهٔ پروژه ساخته می‌شن. اگر می‌خواهید بخش هوش مصنوعی رو تست کنید،
کلید مخصوص توسعه و اتصال شبکه لازم دارید. کلید رو فقط توی `OPENAI_API_KEY` سمت سرور بگذارید،
نه توی متغیرهای `NEXT_PUBLIC_*`. تا وقتی اون بخش رو تست نمی‌کنید، تنظیم مدل نمونه رو تغییر ندید.

## کلون و آماده‌سازی فایل‌ها

از فولدری که پروژه‌ها رو توی اون نگه می‌دارید، این دستورها رو با بش یا پاورشل بزنید:

```bash
git clone https://git.alpagency.net/alp/gandom-kiosk.git
cd gandom-kiosk
node scripts/setup-dev-env.mjs
npm --prefix frontend ci
```

اسکریپت راه‌اندازی، اگر `backend/.env` و `frontend/.env.local` وجود نداشته باشن، اون‌ها رو می‌سازه
و برای Django یک کلید محلی تولید می‌کنه. فایل‌های قبلی رو تغییر نمی‌ده؛ اگر این فایل‌ها رو از قبل دارید،
مقدارهای محلی‌شون رو خودتون بررسی کنید. اجرای دوبارهٔ اسکریپت تنظیمات قبلی رو عوض نمی‌کنه.

| فایل | تنظیم محلی |
| --- | --- |
| `backend/.env` | `DEBUG=True`، `SQLITE_PATH=db.sqlite3`، هاست‌های `localhost,127.0.0.1` و `OPENAI_API_KEY=` |
| `frontend/.env.local` | `NEXT_PUBLIC_BACKEND_BASE_URL=http://localhost:8000` و `OPENAI_API_KEY=` |
| هر دو فایل | `ADMIN_ACCESS_KEY` توی بک‌اند و `NEXT_PUBLIC_ADMIN_KEY` توی فرانت‌اند، هر دو `local-kiosk-admin-only` |

پنل اختصاصی فعلی، کلید رو از کدی می‌فرسته که توی مرورگر قابل دیدنه.
مقدار نمونه فقط برای توسعهٔ محلیه؛ کلید پروداکشن رو اینجا نگذارید.
این کلید با نام کاربری و پسورد پنل Django فرق داره.

## ترمینال اول: نصب و آماده‌سازی بک‌اند

از فولدر اصلی ریپو شروع کنید. لینوکس با بش:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py import_perfumes_from_json --source frontend/public/data/data.json
python manage.py shell -c "from api.models import Perfume; print(Perfume.objects.count())"
python manage.py runserver 127.0.0.1:8000
```

ویندوز با پاورشل:

```powershell
Set-Location backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py import_perfumes_from_json --source frontend/public/data/data.json
python manage.py shell -c "from api.models import Perfume; print(Perfume.objects.count())"
python manage.py runserver 127.0.0.1:8000
```

اگر پاورشل اجازهٔ فعال‌کردن محیط پایتون رو نداد، به‌جای `python` از
`.\.venv\Scripts\python.exe` استفاده کنید. لازم نیست execution policy کل سیستم رو تغییر بدید.
همهٔ دستورهای `manage.py` رو از فولدر `backend` بزنید.

مایگریشن جدول‌ها رو می‌سازه، ولی عطرها رو وارد نمی‌کنه. دستور ایمپورت، مسیر `--source` رو نسبت به
**فولدر اصلی ریپو** می‌خونه، با اینکه خود دستور رو از `backend` اجرا می‌کنید.
فایل فعلی 258 عطر با آیدی عددی داره؛ بعد از ایمپورت، دیتابیس تازه باید 258 ردیف داشته باشه.
اگر دوباره ایمپورت کنید، همون آیدی‌ها به‌روز می‌شن و ردیف تکراری ساخته نمی‌شه، ولی ممکنه تغییرهایی که خودتون روی اون محصولات دادید جایگزین بشن.
فقط اگر می‌خواهید کاتالوگ محلی رو پاک کنید، `--reset` بگذارید. فایل دیگر، یعنی `backend/perfumes.json`،
با هر بار ایمپورت ردیف جدید می‌سازه؛ برای تکرار مراحل راه‌اندازی از اون استفاده نکنید.

## ترمینال دوم: اجرای فرانت‌اند

یک ترمینال دیگر توی فولدر اصلی ریپو باز کنید و این دستور رو با بش یا پاورشل بزنید:

```bash
npm --prefix frontend run dev
```

Django روشن بمونه. http://localhost:3000 رو باز کنید و با دکمهٔ شروع به `/questionnaire` برید.
سلیقه‌ها رو انتخاب کنید و پرسش‌ها رو تا آخر جواب بدید؛ باید عطرهایی از کاتالوگی که وارد کردید پیشنهاد بشن.
اگر کلید OpenAI خالی باشه، ممکنه پیام `OPENAI_API_KEY not set - using baseline` رو توی لاگ ببینید.
در این حالت، پیشنهادهای پایهٔ پروژه نمایش داده می‌شن و این رفتار طبیعیه.

برای چک‌کردن بک‌اند، توی لینوکس `curl http://localhost:8000/api/perfumes/` و توی پاورشل
`Invoke-RestMethod http://localhost:8000/api/perfumes/` رو بزنید.
باید HTTP 200 و یک لیست JSON غیرخالی از عطرها بگیرید. مسیر `/health` نداریم و `/api/` به‌تنهایی هم برای چک سلامت نیست.

برای دیدن پنل اختصاصی، http://localhost:3000/admin/products رو باز کنید.
حساب ورود ازپیش‌ساخته نداریم؛ این پنل از همون کلیدهای محلی یکسان استفاده می‌کنه.
ایمپورت، رکوردهای عطر رو می‌سازه، ولی رکوردهای جداگانهٔ برند و کالکشن رو نمی‌سازه؛
پس خالی‌بودن صفحهٔ مدیریت برند یا کالکشن به این معنی نیست که ایمپورت شکست خورده.
اگر تغییرتون به این رکوردها نیاز داره، از صفحه‌های مدیریتشون دیتای تست اضافه کنید.
ایمپورت JSON وجود عکس برای همهٔ عطرها رو تضمین نمی‌کنه؛ برای کار روی آپلود عکس،
تصویر تست محلی توی فضای `backend/media` لازم دارید.

اگر پنل جداگانهٔ Django رو توی http://localhost:8000/admin/ می‌خواهید، بک‌اند رو با Ctrl+C متوقف کنید
و توی همون فولدر، با محیط پایتون فعال، این دستورها رو بزنید:

```bash
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8000
```

نام کاربری و پسورد محلی رو خودتون انتخاب کنید؛ حسابی همراه پروژه نیست.
این حساب، کلید پنل اختصاصی فرانت‌اند رو تنظیم نمی‌کنه.

## تست تغییرها

توی `backend` و با محیط پایتون فعال، این دستورها رو بزنید:

```bash
python manage.py check
python manage.py test
```

Django برای تست‌ها دیتابیس SQLite جداگانه می‌سازه. تست‌های فعلی API، اعتبارسنجی پرسش‌نامه رو پوشش می‌دن.
اگر منطق پیشنهاد عطر یا پنل مدیریت رو تغییر دادید، عملکردشون رو دستی هم تست کنید.
برای تغییر ساختار دیتا هم مایگریشن بسازید و بازبینی کنید.

توی یک ترمینال جدا، از فولدر `frontend` و نه فولدر اصلی ریپو، این دستورها رو بزنید:

```bash
npm run lint
npm exec --no -- tsc --noEmit
npm run test -- --run
npm run build
```

گزینهٔ `--no` اجازه نمی‌ده ابزار نصب‌نشده دانلود بشه؛ اول `npm ci` رو اجرا کنید.
قبل از چک build، سرور توسعهٔ فرانت‌اند رو متوقف کنید تا خروجی‌ها با هم قاطی نشن.
برای یک تغییر محدود توی رابط، اول lint، تایپ‌چک و تست‌های مرتبط Vitest رو بزنید.
اگر مسیرها، تنظیمات یا کد سرور رو تغییر دادید، build رو هم چک کنید.
مسیر تغییریافته رو توی مرورگر، با اندازهٔ دسکتاپ و کیوسک، متن فارسی و راست‌به‌چپ و دکمه‌های قابل لمس تست کنید.

## توقف و رفع خطاهای رایج

هر سرور رو با Ctrl+C متوقف کنید. دیتابیس SQLite توی `backend/db.sqlite3` و فایل‌های آپلودشده روی سیستم باقی می‌مونن؛
اون‌ها رو کامیت نکنید. برای اجرای محلی به اسکریپت‌های قدیمی داکر یا VPS نیاز ندارید.
CI توی GitLab تغییرها رو چک می‌کنه و روش قدیمی دیپلوی رو اجرا نمی‌کنه.

| مشکل | چی رو بررسی کنید؟ |
| --- | --- |
| موقع کلون ریپو خطای دسترسی می‌گیرید | دسترسی حساب GitLab به این ریپو و تنظیمات ورود Git رو بررسی کنید. |
| خطای `No module named django` می‌گیرید | محیط `backend/.venv` رو فعال کنید و `backend/requirements.txt` رو با پایتون همون محیط نصب کنید. |
| خطای `no such table: api_perfume` می‌گیرید | از `backend`، دستور `python manage.py migrate` رو با تنظیمات SQLite محلی بزنید. |
| کاتالوگ یا پیشنهادها خالیه | فایل کاتالوگ با آیدی عددی رو ایمپورت کنید، تعداد ردیف‌ها رو ببینید و هر دو سرور رو دوباره اجرا کنید؛ دیتای تطبیق بک‌اند و کاتالوگ فرانت‌اند کش می‌شن. |
| فایل ایمپورت پیدا نمی‌شه | از `--source frontend/public/data/data.json` نسبت به فولدر اصلی ریپو استفاده کنید؛ `manage.py` رو از `backend` بزنید. |
| API وصل نمی‌شه یا فرانت‌اند 502 می‌ده | Django باید روی پورت 8000 روشن باشه و `NEXT_PUBLIC_BACKEND_BASE_URL` درست تنظیم شده باشه؛ بعد از تغییر `.env.local`، Next.js رو دوباره اجرا کنید. |
| پنل اختصاصی 401 می‌ده | `NEXT_PUBLIC_ADMIN_KEY` و `ADMIN_ACCESS_KEY` باید یکی باشن؛ هر دو پروسه رو دوباره اجرا کنید. ورود superuser توی Django به این کلید ربطی نداره. |
| پورت 8000 یا 3000 اشغال شده | پروسهٔ محلی دیگری رو که از پورت استفاده می‌کنه متوقف کنید. اگر پورت رو عوض کردید، آدرس بک‌اند و originهای مجاز رو هم با هم تغییر بدید و سرورها رو دوباره اجرا کنید. |
| اسکریپت راه‌اندازی می‌گه فایل‌ها نگه داشته شدن | فایل‌های قبلی تغییر نمی‌کنن؛ آدرس‌ها و کلیدهای محلی رو بررسی کنید. مقدارهای نمونهٔ جدید خودکار جای اون‌ها نمی‌شینن. |
| اسکریپت از قفل باقی‌مانده خطا می‌ده | قبل از حذف `.dev-env-setup.lock` مطمئن بشید اسکریپت راه‌اندازی دیگری در حال اجرا نیست؛ بعد دوباره امتحان کنید. |
| پیام نبود کلید هوش مصنوعی می‌بینید | پیشنهادهای پایه برای توسعهٔ محلی کافیه و تست این مسیر به کلید نیاز نداره. |

برای روال برنچ و بازبینی، [راهنمای GitLab این ریپو](gitlab-workflow.fa.md)،
[راهنمای مشارکت](../CONTRIBUTING.md) و [سیاست امنیتی](../SECURITY.md) رو ببینید.

## چک محیط محلی با doctor

قبل از اجرای سرویس‌ها، از فولدر اصلی ریپو این دستور رو بزنید:

```bash
node scripts/dev-doctor.mjs --before-start
```

بعد از اجرای سرویس‌های همین راهنما:

```bash
node scripts/dev-doctor.mjs --running
```

قبل از شروع، پورت‌های لازم باید آزاد باشن؛ با `--running` باید سرویس‌های ذکرشده در راهنما روشن باشن. doctor نسخهٔ ابزارها، فایل‌های env محلی، آدرس‌ها و پورت‌ها رو چک می‌کنه. کد خروج `0` یعنی چک‌ها پاس شدن، `2` یعنی ابزار یا تنظیمات نیاز به اصلاح داره و `3` یعنی وضعیت پورت یا سرویس درست نیست. اسم گزینه و نسخهٔ ابزار رو می‌بینید، ولی رمزها چاپ نمی‌شن. این دستور پکیج نصب نمی‌کنه، تنظیمات یا سرویس‌ها رو تغییر نمی‌ده و به سرویس بیرونی درخواست نمی‌فرسته. موردی رو که FAIL شده بررسی کنید و دوباره دستور رو بزنید.
