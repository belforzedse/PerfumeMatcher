# کار تیمی توی گیت‌لب

[English](gitlab-workflow.md)

برای هر کار یک ایشو باز کنید: چی باید عوض بشه، چه کسی انجامش می‌ده و کی کار تمومه؟ هر نفر با یک کار شروع کنه. کاری که بیشتر از یکی دو روز طول می‌کشه رو به چند MR کوچک‌تر تقسیم کنید تا ریویوش راحت باشه.

## از ایشو تا مرج

۱. ایشو رو به خودتان اساین کنید و لیبل «در حال انجام» بزنید.
۲. از آخرین نسخهٔ main یک برنچ بسازید. توی مثال زیر، 123 شمارهٔ فرضی ایشوئه؛ شمارهٔ ایشوی خودتان رو جایش بگذارید.

```bash
git status
git switch main
git pull --ff-only
git switch -c feature/123-short-description
```

اگر تغییر کامیت‌نشده دارید، اول تکلیفش رو مشخص کنید. pull یا عوض‌کردن برنچ نباید کار قبلی‌تان رو از بین ببره.

۳. تغییر رو انجام بدید، تست‌ها و چک‌های مربوط به آن رو بزنید و فقط فایل‌های همین کار رو stage کنید.

```bash
git diff
git add path/to/changed-file
git diff --cached
git commit -m "Describe the change"
git push -u origin HEAD
glab mr create --draft --template Default
```

مسیر نمونه رو با فایل واقعی عوض کنید. برای MR فارسی از Default و برای انگلیسی از Default.en استفاده کنید. این دستورها توی بش و پاورشل کار می‌کنن.

۴. توی MR بنویسید چی عوض شده و چه تست‌هایی زدید. اگر ایشو واقعاً تموم شده، `Closes #123` رو توی توضیح بگذارید. برای تغییر UI، اسکرین‌شات یا ویدئوی کوتاه از دادهٔ تستی بگذارید.
۵. وقتی آمادهٔ ریویو شد، MR رو از Draft دربیارید، یک ریویور انتخاب کنید و ایشو رو به «منتظر بررسی» ببرید. هم‌تیمی‌ها می‌تونن ریویوی اولیه رو انجام بدن؛ مرج نهایی با مسئول پروژه‌ست.
۶. کامنت‌های باز رو پیگیری کنید. وقتی تغییر رو انجام دادید یا با ریویور به توافق رسیدید، دیسکاشن رو resolve کنید. بعد از مرج، برنچ موقت حذف می‌شه؛ ایشویی که تموم شده رو ببندید.

## برد و لیبل‌ها

| لیبل | کی استفاده کنیم؟ |
| --- | --- |
| آماده | کار مشخصه و می‌تونیم شروعش کنیم. |
| در حال انجام | یک نفر مشغول انجام این کاره. |
| منتظر بررسی | MR آماده‌ست و منتظر ریویو هستیم. |
| نیاز به پیگیری | منتظر پاسخ، دسترسی یا تصمیم هستیم. دلیلش رو توی ایشو بنویسید. |

هر ایشو فقط یکی از سه وضعیت اصلی رو داشته باشه. «نیاز به پیگیری» رو می‌تونید کنار وضعیت فعلی بگذارید. نوع کار رو هم با «باگ»، «قابلیت جدید»، «نگهداری» یا «مستندات» مشخص کنید. وقتی ایشو رو ببندید، به ستون Closed می‌ره.

## وقتی گیر می‌کنید

توی همان ایشو بنویسید چی رو امتحان کردید، چه نتیجه‌ای گرفتید و دقیقاً چه کمکی لازم دارید. نسخهٔ ابزار، دستور و بخش مهم خطا رو بگذارید؛ رمز و اطلاعات حساس رو حذف کنید. با «کار نمی‌کنه» به‌تنهایی، پیدا کردن مشکل سخت می‌شه.

## مرج و دیپلوی

main برنچ مشترک تیمه. تغییرها از MR واردش می‌شن؛ push مستقیم و force push روی آن بسته‌ست. ریویوی نهایی و مرج با Maintainer است. CI سبز یعنی چک‌های خودکار پاس شده‌اند. برای دیپلوی، مسئول پروژه باید مرحلهٔ انتشار روی سرور رو جداگانه اجرا و نتیجه رو چک کنه.

کلیدها، رمزها و env پروداکشن رو از مسیر تعیین‌شدهٔ مسئول پروژه بگیرید. آن‌ها رو توی ایشو، MR، اسکرین‌شات یا گیت نگذارید. برای تست از حساب و دادهٔ تستی استفاده کنید.
